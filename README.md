# Pioneers Academy — حزمة MVP مستقلة

تطبيق عربي لإدارة أكاديمية تدريب وبرامج مهنية: دورات، دبلومات، ماجستير مهني ودكتوراه مهنية، مع إمكانية إضافة أنواع برامج أخرى. واجهة RTL، خط Cairo محلي، كحلي وذهبي وسماوي مستوحى من الصورة المرجعية. لا تتضمن الحزمة الصورة الأصلية أو بيانات التواصل الظاهرة فيها.

**هذه حزمة مصدر قابلة للتشغيل والتطوير، وليست خدمة منشورة.** لم يُنشأ مستودع أو مشروع Neon خارجي ولم يُستخدم أي مورد من مشروع المدرسة.

## الموجود فعليًا

- دخول بالبريد وكلمة المرور، جلسات محفوظة في قاعدة البيانات، تغيير كلمة المرور، تعطيل الحسابات وإنهاء جلساتها.
- أدوار الإدارة والشؤون الأكاديمية والمحاضر والمالية والطالب. جميع صلاحيات القراءة والكتابة تُفحص على الخادم.
- لوحة مؤشرات فعلية من البيانات، وبرامج وأنواع برامج وتخصصات ودفعات ومقررات.
- إنشاء حسابات الطلاب والمحاضرين، رقم طالب آلي، حالات قبول، تسجيلات ونسبة إنجاز وحالة إكمال.
- جداول المحاضرات، تسجيل الحضور وتعديله. المحاضر يصل فقط لمحاضراته وطلاب دفعاته.
- اختبارات اختيار من متعدد: أربع إجابات، إجابة صحيحة واحدة، مسودة ثم نشر، محاولة واحدة، تصحيح ونتيجة على الخادم.
- رسوم وأقساط كفواتير، مدفوعات جزئية، أرصدة محسوبة، إيصالات قابلة للطباعة، ومصروفات.
- شهادات للتسجيلات المكتملة 100%، إلغاء شهادة، صفحة تحقق عامة وQR وطباعة إلى PDF من المتصفح.
- بوابة طالب لبرامجه وجدوله وحضوره واختباراته ونتائجه وفواتيره وإيصالاته وشهاداته.
- migration SQL، seed اختياري، سجل تدقيق، واختبارات تكامل.

## 1. رفع الملفات يدويًا إلى GitHub

1. فك ضغط `Pioneers-Academy.zip`.
2. افتح مجلد `Pioneers-Academy` الناتج.
3. ارفع **محتويات المجلد** إلى جذر مستودع `Pioneers-Academy`؛ يجب أن يكون `package.json` في الجذر.
4. تأكد من رفع `.gitignore` و`.env.example` و`pnpm-lock.yaml` و`pnpm-workspace.yaml` أيضًا؛ قد يخفي نظامك الملفات التي تبدأ بنقطة.
5. لا ترفع `.env` أو `node_modules` أو كلمات مرور. ملف ZIP لا يحتوي على هذه الأسرار أو الاعتماديات المثبتة.

## 2. المتطلبات

- Node.js 22 حديث أو Node.js 24.
- pnpm 11.19.0، ويمكن تثبيته بواسطة `npm install -g pnpm@11.19.0`.
- للتشغيل الحقيقي: مشروع Neon **جديد مستقل** وقاعدة PostgreSQL خالية.

من داخل المجلد:

```sh
pnpm install --frozen-lockfile
```

## 3. معاينة سريعة دون Neon

```sh
pnpm build
pnpm preview:demo
```

افتح `http://localhost:3000`. يعرض الطرفية كلمة مرور عشوائية مؤقتة للمعاينة. تستخدم الحسابات أدناه هذه الكلمة في المعاينة فقط:

| الحساب | الدور |
|---|---|
| admin@example.test | المدير |
| academic@example.test | الشؤون الأكاديمية |
| finance@example.test | المالية |
| lecturer@example.test | المحاضر |
| student@example.test | طالبة لها تسجيلات وبيانات تجريبية |
| student2@example.test | طالب ثان لاختبار عزل البيانات |

المعاينة تربط الخادم بعنوان loopback فقط وتستخدم PGlite في الذاكرة. تُحذف بياناتها بمجرد إيقاف العملية، ولا تتصل بـ Neon. لا تستخدمها للنشر أو البيانات الحقيقية، وهي ممنوعة عند `NODE_ENV=production`.

## 4. إعداد قاعدة Neon الجديدة

أنشئ مشروعًا جديدًا باسم واضح مثل `pioneers-academy` من لوحة Neon. انسخ رابط الاتصال **المجمّع pooled** للتطبيق، والرابط **المباشر direct** للمهاجرات. احتفظ بالمصادقة المشفرة والتحقق من شهادة TLS؛ المثال يستخدم `sslmode=verify-full`.

انسخ `.env.example` إلى `.env`:

```powershell
# Windows PowerShell
Copy-Item .env.example .env
```

```sh
# macOS / Linux
cp .env.example .env
```

حرر `.env` محليًا:

- `DATABASE_URL`: اتصال Neon pooled الجديد.
- `DATABASE_URL_DIRECT`: الاتصال المباشر **لنفس القاعدة الجديدة**.
- `APP_ORIGIN=http://localhost:5173` للتطوير، دون شرطة مائلة أخيرة.
- `SEED_ADMIN_EMAIL`: بريد المدير الذي تختاره.
- `SEED_ADMIN_PASSWORD`: كلمة مرور تختارها، 12 حرفًا على الأقل.
- `SEED_DEMO=false` لحساب المدير وأنواع البرامج فقط، أو `true` لبيانات العرض.
- عند تفعيل العرض، اختر `SEED_DEMO_PASSWORD` مستقلة، 12 حرفًا على الأقل.

```sh
pnpm db:migrate
pnpm db:seed
pnpm dev
```

افتح `http://localhost:5173` وسجّل الدخول بحساب المدير. seed يرفض العمل إذا كان جدول المستخدمين غير فارغ، فلا يمس بيانات سابقة. لا توجد كلمة مرور إنتاج افتراضية. احذف متغيرات كلمات مرور seed بعد نجاح الإنشاء.

المهاجرات تُنفَّذ داخل transaction مع قفل ومنع تغيير migration سبق تطبيقها عبر checksum. عند التطوير أضف migration مرقمة جديدة بدل تعديل `0001_initial.sql` بعد تطبيقها. ملفات SQL هي مخطط البيانات المرجعي، وتنفذها طبقة Drizzle في الخادم.

## 5. سير العمل الأول

1. أضف نوع البرنامج ثم البرنامج والتخصص والدفعة والمقرر.
2. أضف المحاضر والطالب؛ يتولد رقم الطالب آليًا. اضبط القبول إلى «مقبول».
3. أنشئ تسجيلًا للطالب في دفعة وبرنامج متطابقين. التخصص إن حددته يجب أن يتبع البرنامج نفسه.
4. أضف المحاضرات بالبرنامج والمقرر والدفعة والمحاضر ووقت البداية والنهاية. يُحفظ الوقت UTC ويُعرض بتوقيت المتصفح.
5. سجّل الحضور؛ يرفض الخادم طالبًا غير مسجل في الدفعة.
6. أضف اختبارًا غير منشور، ثم أسئلته، ثم عدّل الاختبار ليصبح منشورًا. لا يمكن تعديل الأسئلة المنشورة، أو الاختبار بعد وجود محاولة.
7. أضف فاتورة لكل قسط ثم المدفوعات، مع مرجع فريد لكل دفعة. يمنع الخادم تجاوز المتبقي، بما فيه الطلبات المتزامنة.
8. اعتمد الإكمال إداريًا واضبط الإنجاز 100% والحالة «مكتمل»، ثم أصدر الشهادة.

نسبة الإنجاز وحالة الإكمال يحددهما الموظف المخول في هذا MVP؛ لا يُستنتجان تلقائيًا من الحضور أو الاختبارات. مبالغ النظام موحدة بعملة واحدة تختارها الأكاديمية؛ العرض الحالي «وحدة نقدية» لعدم افتراض دولة أو عملة.

## 6. البناء والاختبار

```sh
pnpm test
pnpm build
```

الاختبارات تنشئ PostgreSQL متوافقة محليًا عبر PGlite دون credentials أو cloud، وتفحص المهاجرات والصلاحيات والعزل والتصحيح والمالية والشهادات والجلسات. التفاصيل في `docs/TESTING.md`.

للتجربة المحلية بعد البناء مع Neon: استخدم `APP_ORIGIN=http://localhost:3000` و`NODE_ENV=development` ثم `pnpm start`. التشغيل الإنتاجي يتطلب HTTPS.

## 7. النشر

التطبيق **خدمة Node.js كاملة** تقدم ملفات `dist` وواجهات `/api` من النطاق نفسه، وليس موقعًا ثابتًا يصلح لـ GitHub Pages.

1. اربط المستودع بخدمة استضافة تدعم Node.js أو Docker، مثل Web Service على Render أو حاوية على خادمك.
2. أمر البناء: `pnpm install --frozen-lockfile && pnpm build`.
3. أمر التشغيل: `pnpm start`.
4. أضف في أسرار منصة الاستضافة: `DATABASE_URL` الجديد، و`NODE_ENV=production`، و`APP_ORIGIN=https://your-domain.example` دون `/` أخيرة. `PORT` تعيّنه المنصة أو يساوي 3000.
5. نفّذ المهاجرات وseed مرة واحدة من جهازك أو مهمة إدارية آمنة باستخدام `DATABASE_URL_DIRECT`. لا تجعل seed جزءًا من إعادة تشغيل الخادم. يمكن حذف متغير الاتصال المباشر من خدمة التطبيق بعد ذلك.
6. فعّل HTTPS على نفس النطاق المستخدم في `APP_ORIGIN`. الكوكيز الإنتاجية Secure ولن تعمل عبر HTTP.
7. اختبر تسجيل الدخول، حساب طالب، دفع جزئي، اختبار وشهادة وفتح رابط QR من هاتف.

اختياريًا: `docker build -t pioneers-academy .` ثم شغّل الحاوية بأسرار الخادم، وخلف reverse proxy يوفر HTTPS. Dockerfile متعدد المراحل، ولا يتضمن `.env`، ويشغّل التطبيق بمستخدم غير root. لم تُنفذ عملية نشر سحابية أو تجربة Docker ضمن إعداد هذه الحزمة.

## 8. الملفات

```text
src/                  واجهة React + RTL + Cairo + استدعاءات API
server/app.js         HTTP API، تسجيل الدخول، التفويض، التحقق والتصحيح
server/catalog.js     نماذج الحقول وقواعد التحقق ومصفوفة صلاحيات الوحدات
server/security.js    تشفير كلمات المرور ورموز الجلسات
server/db.js          Drizzle / node-postgres، على الخادم فقط
migrations/           مخطط PostgreSQL وملفات التغييرات
scripts/              migrate، seed، المعاينة، استعادة كلمة المرور
tests/                اختبارات التكامل
docs/                 المعمارية والأمن والاختبار وحدود الإصدار
.env.example          أسماء الإعدادات فقط دون أسرار
Dockerfile            خيار نشر كحاوية
pnpm-lock.yaml        قفل إصدارات الاعتماديات
```

## 9. حدود هذا الإصدار

انظر `docs/SCOPE.md` قبل تشغيله على بيانات حقيقية. لا تشمل النسخة: دفع إلكتروني، ضرائب أو محاسبة مزدوجة، استرداد مالي، حذف السجلات، رفع مستندات، فيديو وبث، رسائل بريد/SMS، استعادة كلمة المرور بالبريد، MFA، مراقبة اختبارات أو اعتماد أكاديمي خارجي. البيانات المالية المسجلة نهائية من الواجهة؛ التصحيحات المالية تتطلب تطوير دفتر تسويات قبل اعتماد النظام ماليًا على نطاق تشغيلي.

استعادة كلمة مرور بواسطة مشغّل موثوق: عيّن `RESET_EMAIL` و`RESET_PASSWORD` في بيئة خاصة ثم `pnpm admin:reset-password`، واحذفهما بعد التشغيل. الأداة تنهي جلسات الحساب وتسجل العملية ولا تطبع كلمة المرور.

المصدر الرسمي لإعداد الاتصال: [Neon — Connection pooling](https://neon.com/docs/connect/connection-pooling) و[node-postgres — SSL](https://node-postgres.com/features/ssl).
