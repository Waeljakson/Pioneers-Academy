# نشر التطبيق الحقيقي

[فتح إعداد النشر على Render](https://render.com/deploy?repo=https://github.com/Waeljakson/Pioneers-Academy)

ملف render.yaml ينشئ Web Service تشغّل الواجهة والخادم من نطاق واحد. يطلب Render إدخال الأسرار في لوحته، ولا تظهر في ملفات GitHub.

المطلوب: مشروع Neon جديد مستقل للأكاديمية، وحساب Render يسمح بإنشاء خدمة. لم يُنشئ هذا التعديل قاعدة بيانات أو خدمة مدفوعة.

- DATABASE_URL: اتصال pooled بالمشروع الجديد.
- DATABASE_URL_DIRECT: الاتصال direct بالمشروع الجديد نفسه؛ يُستخدم في تهيئة المخطط عند بدء النشر.
- SEED_ADMIN_EMAIL: بريد دخول المدير الذي تختاره.
- SEED_ADMIN_PASSWORD: كلمة مرور أولية قوية لا تقل عن 12 حرفًا.

يؤخذ عنوان التطبيق تلقائيًا من RENDER_EXTERNAL_URL؛ لا حاجة لتخمين النطاق. عند استخدام نطاق خاص، اضبط APP_ORIGIN على عنوان HTTPS الكامل دون مسار.

أول تشغيل يطبق المهاجرات وينشئ المدير وأنواع البرامج فقط. كل تشغيل لاحق يحافظ على الحسابات والبيانات ولا يعيد تعيين كلمات المرور، ولا يُدخل بيانات العرض التجريبية. بعد نجاح أول تشغيل، احذف SEED_ADMIN_PASSWORD وSEED_ADMIN_EMAIL من بيئة الخدمة؛ إعادة النشر لا تحتاجهما على قاعدة مستخدمة.

الخطة المحددة free لتجنب بدء خدمة مدفوعة تلقائيًا. هي بداية لتجربة التطبيق الحقيقي المتصل بالبيانات، وليست ضمان توافر للإنتاج التجاري؛ تختار الأكاديمية خطة مناسبة لاحقًا إذا احتاجت تشغيلًا دائمًا.

بعد الحصول على رابط Render النهائي، حدّث رابط الموقع في GitHub أو حوّل صفحة GitHub Pages إليه. Pages لا تستضيف خادم Node.js.

المراجع: [Render Blueprint](https://render.com/docs/blueprint-spec)، [حدود الخطة المجانية](https://render.com/docs/free).
